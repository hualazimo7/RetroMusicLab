## 1. 展开怎么做：三条路，选改行高

| | A 改 `.app` 第三行高度（**推荐**） | B deck 绝对定位浮层 | C 覆盖 workspace 遮罩 |
|---|---|---|---|
| 实现 | `grid-template-rows` 第三行 `86px → 86+deckH` | `position:fixed; bottom:0` + `transform:translateY` | 全屏遮罩 + 居中面板 |
| 是否遮挡主区 | 不遮挡，主区自然变矮 | **遮挡**（盖在 inspector 上） | 完全遮挡 |
| 动画 | 轨道尺寸可插值，200ms 顺滑 | transform 动画最顺 | 淡入 + 缩放 |
| 宽度基准 | 全宽，与三栏天然对齐 | 需自己算宽度/内边距 | 需自己算 |
| 风险 | 低（见下方前提） | 中（层级、点击穿透） | 高（相当于第二个界面） |

**A 可行的前提**（已核实）：三栏都能内部滚动，行高变小不会把内容挤坏：

- `.src-list { flex:1; min-height:0; overflow-y:auto }`（`app.css:301-304`）—— 左栏列表自己滚
- `.inspector { min-height:0; overflow-y:auto }`（`app.css:614-619`）—— 右栏整体自己滚
- `.stage { min-height:0 }`（`app.css:409`），内部列表自己滚

所以「展开 → 主区变矮 → 三栏各自滚」是安全行为，不需要给主区加 `overflow: auto`（早先文档多虑了）。

### 高度预算（实测公式）

```css
.app { grid-template-rows: 50px minmax(0,1fr) var(--dock-h, 86px); }
.app.deck-open { --dock-h: clamp(236px, 32vh, 386px); }  /* 386 = 86 收起条 + 300 面板 */
```

| 视口高 | `--dock-h` | 面板净高 | 主区剩余 |
|---|---|---|---|
| 700 | 236（触底） | 150 | 414 |
| 800 | 256 | 170 | 494 |
| 900 | 288 | 202 | 562 |
| 1080 | 346 | 260 | 684 |

加一条兜底：`主区剩余 = 视口 − 50 − --dock-h`，低于 360 时改用媒体查询把面板压到 180。按上表，**700 以上不需要额外处理**。

## 2. 结构改造（精确到 DOM）

现在第三行直接是 `<footer class="dock">`。改造后包一层，`dock` 内部**一行不动**：

```html
<!-- 之前 --> <footer class="dock"> … </footer>
<!-- 之后 -->
<footer id="deck" class="deck">
  <div class="dock"> …原有内容原样… </div>
  <div class="deck-body" hidden> …卡带 / 表盘 / 旋钮… </div>
</footer>
```

为什么包一层而不是直接改 `.dock`：`.dock` 是 3 列 grid（`232px / 1fr / 340px`，`app.css:958`），
如果往里塞卡带面板，三列宽度的语义会被第二行内容污染。包一层后 `.dock` 保持「一行 86px」不变，
`#deck` 变成 `display:flex; flex-direction:column`，`deck-body` 吃剩余高度。

**列对齐**：`deck-body` 用 `padding: 0 14px 0 16px; grid-template-columns: 232px minmax(0,1fr) 340px`，
与 `.dock` 参数完全一致 —— 卡带窗左边缘会和「正在播放」封面左边缘齐平。
（`.dock` 左列 232 + 16 padding = 248，与 `.rail` 的 260 有 12px 既有错位，属现有排版，本次不动。）

**性能细节**：`.dock` 现在有 `backdrop-filter: blur(16px)`。`deck-body` **不要**沿用，
大面积实时模糊在 4K 屏会掉帧，用 `color-mix(in srgb, var(--surface) 92%, transparent)` 实色即可。

## 4. 数据通路：只加 3 个接口，音频图不许出 viz.js

```js
viz.onFrame(fn)          // 每帧回调 { freq, wave, live }，deck 的 VU / LED 都从这里取
viz.setEq(bassDb, treble) // 内部改链：src → lowshelf → highshelf → analyser → destination
viz.colors()             // { a, b, dim }，与频谱同一套主题色
```

**不变量（写进代码注释）**：外部永远拿不到 `ctx` / `analyser` 自己去 `connect()`。
一旦外部接线，`viz.js:11-21` 注释里那三条坑（只连一次、必须接 destination、断开就静音）就会重演，
而且出错时表现为「频谱漂亮但没声音」，极难定位。

**必须做「保活」**：`viz.js:284` 的循环开头是 `if (!V.on) { V.raf = 0; return; }`，
`setOn(false)` 还会直接 `cancelAnimationFrame`（`viz.js:305-315`）。
也就是说用户一旦关掉「显示可视化」开关，deck 的 VU 会**僵在最后一次读数**。
所以 `onFrame` 注册后要改这段判断：`V.on` 只控制「画不画 canvas」，不再决定「跑不跑循环」——
有消费者就继续跑，只是跳过绘制。这是整条路径里最容易漏的一处。

## 5. 音频图改造顺序（4 步，每步可独立回滚）

1. `ensure()` 里多建两个 `BiquadFilterNode`：`lowshelf`（200Hz）、`highshelf`（3kHz），`gain = 0`；
2. 连接从 `src → an → destination` 改成 `src → low → high → an → destination`，
   **先用 `disconnect()` 拆旧的，再连新的**，绝不并存（并存 = 双倍音量 + 相位漂移）；
3. `setEq()` 用 `setTargetAtTime(v, ctx.currentTime, 0.02)`，直接赋值会「啪」一声；
4. `ensure()` 是懒建的（第一次播放才建），所以 `setEq` 在未初始化时要把值挂在 `V.pendingEq`，
   建完图立刻补应用 —— 否则「先拧旋钮再播放」的那次设置会丢。

**导出为什么天然不受影响**：导出全在 Python 侧完成（`msu1_to_cd.py` / `dl_convert.py` / `wavmerge.py`），
Web 端 `<audio>` 只播 `/api/audio?id=` 的产物，不参与任何编码。
这条要在文档和 UI 上都写明白，用户才不会以为 BASS 会影响成品。

## 6. 仪表数学（先定公式，别边写边试）

**VU 表**（数据源 `wave`，时域字节）：

```
rms  = sqrt(mean(((v - 128) / 128)^2))          // v 取自 getByteTimeDomainData
db   = 20 * log10(max(rms, 1e-6))               // 实测安静段 -55 ~ -45，满幅约 -6 ~ -3
ang  = -42 + 84 * clamp((db + 40) / 40, 0, 1)   // -40dB → -42°，0dB → +42°
```

指针动效：起针立即（`ang` 直接赋值），落针 `300ms` 缓释，否则低频一跳一跳地抖。

**15 列 LED**：沿用 `viz.js:215` 的取样公式，只改列数，不另写一套：

```
t   = i / 14                                     // 0..1
bin = floor(t^1.85 * freq.length * 0.62)
v   = max(freq[bin-3 .. bin+3]) / 255            // ±3 bin 取 max，避免漏掉窄峰
```

**双卷盘**（恒定带速，半径反比）：

```
p    = currentTime / duration
rL   = rMin + (rMax - rMin) * (1 - p)            // 左盘由满变空
rR   = rMin + (rMax - rMin) * p                  // 右盘由空变满
ωL   = v / rL ;  ωR = v / rR                     // v ≈ 5.0（归一化线速度，对齐参考对象的 4.8~5.2 rad/s 量级）
rMin = 0.55 ; rMax = 1.0
```

拖动进度条时 `p` 突变 → 转速短暂变化，正好是真实走带的手感；这一点比参考对象的**恒定转速**更像设备
（它只是视觉演示，我们这里必须贴合真实进度）。

## 7. 状态机与 rAF 启停

| 状态 | dock（收起条） | deck-body | rAF |
|---|---|---|---|
| 收起 | 可见 | 隐藏 | 只跑频谱（若正在播放且开关为开） |
| 展开 · 无曲 | 可见 | 显示，表针归零、卷盘静止 | 不跑 |
| 展开 · 播放 | 可见 | 卷盘转、VU 动、LED 亮 | 跑 |
| 展开 · 暂停 | 可见 | 卷盘停、VU 落零、LED 熄灭 | 停（等指针落完再停） |
| 拖动 seek | 可见 | 卷盘转速随 `p` 变化 | 跑 |

启停规则一句话：**「展开 && (播放中 || 指针未落稳)」才跑循环**。其余情形停掉，省电也省 CPU。
