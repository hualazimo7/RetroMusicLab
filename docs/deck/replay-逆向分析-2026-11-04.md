## 5. 卡带几何与走带物理（本次最有价值的可复用部分）

### 5.1 三张卡带照片的精确参数

画布统一 **1536 × 1024**，`shell` 为 `[x, y, w, h, radius]`，`hubs` 为两个 `[cx, cy, r]`：

| 型号 | 图片 | shell | hub L | hub R |
|---|---|---|---|---|
| C60 | `classic-c60-v1.png` | `[32, 68, 1468, 882, 48]` | `[486, 485, 68]` | `[1046, 483, 68]` |
| C90 | `classic-c90-v1.png` | `[58, 70, 1420, 842, 48]` | `[468, 462, 60]` | `[1052, 463, 60]` |
| Metal C90 | `metal-c90-v1.png` | `[48, 64, 1440, 876, 42]` | `[450, 438, 270]` | `[1087, 438, 270]` |

> Metal 的 hub 半径 270 明显大于普通卡带的 60–68：它画的是**整盘金属轮**，不是小轴心。这一条直接解释了「为什么淘宝图里金属带看起来更满」。

### 5.2 卷盘半径：平方根模型（不是线性插值）

```
hL = sqrt(1 - 0.72 * p)
hR = sqrt(0.28 + 0.72 * p)     // p = 0..1 播放进度
```

- **0.72** 是半径平方的变化幅度，**0.28** 是起始剩余比例；
- 用平方根而不是线性：磁带长度 ∝ 半径²，恒带速下半径随剩余长度开方变化 —— 这是物理正确的模型，也是本项目 `实现路径.md` §6 里 `rMin + (rMax-rMin)*(1-p)` **应该替换掉**的写法。

### 5.3 角速度 = 线速度 / 半径

| 状态 | 目标线速度 |
|---|---|
| playing | **1.5** |
| fast-forward | **10** |
| rewind | **-10** |
| 其他 | 0 |
| B 面 | 全部取反 |

- 实际角速度 `ω = v / h`（半径越小转得越快），一阶平滑时间常数 **9**（约 111 ms 到 63%）；
- 帧率上限 **16 ms**（约 60 fps），且只有「角度/内容签名变化」才重绘；
- 这比官网版的 **恒定 5.2 / 4.8 rad/s** 更接近真实走带，也解释了为什么参考产品看起来「转得对」。

### 5.4 磁带时长与翻面

- 单面时长：**C60 = 1800 s**，**C90 = 2700 s**（`tapeLength` 决定，其余按 C60 处理）；
- 进度 `p = (前面曲目累计时长 + currentTime) / 单面时长`，夹在 0..1；
- 翻面动画：`perspective(700px) rotateY`，`0° → 86° → -86° → 0°`，**620 ms**，`ease-in-out`，中点 310 ms 切面；
- 磁带标签按型号有不同绘制矩形（C90：`205,165,1170,170`；C60：`145,154,1250,170`），字体为楷体 43px。

## 6. 音频链与频谱（可直接对照我们的音色引擎）

### 6.1 参考实现的主音频图

```
<audio> → TapeAudioEngine → lowshelf(220Hz) → highshelf(3500Hz)
        → AnalyserNode(fftSize 8192, smoothing 0.78) → GainNode(volume) → destination
```

三个可直接对表的结论：

1. **analyser 在音量之前**，与我们在 `音色引擎-分析.md` §3「analyser 取在 outGain 之前」完全一致；
2. **fftSize 8192** 比常见 2048 高得多，换来 10 段低频更稳的分辨率；`smoothing 0.78`（电台路径用 0.72）；
3. 它的「EQ」只有两颗搁架（220 / 3500），没有 9 段 —— 说明**参考产品的音色卖点不在 EQ 精度，而在磁带染色**，这正是 `音色引擎-分析.md` §0 的判断。

### 6.2 磁带音色参数（真实数值）

| 配置 | 参数 |
|---|---|
| `normal`（preview） | `shelfHz 4500`，`shelfDb -2`，`cutoffHz 15500`，`Q -3.0103` |
| `high`（legacy） | `cutoffHz 16800`，`Q 0.18` |
| `metal` | **bypass**（identity，不做染色） |
| 噪声电平 | **-54 dBFS** |
| 参数过渡 | **0.08 s** |

噪声生成：白噪声经 **高通 1450 Hz + 低通 min(10 kHz, 0.4×sr)** 两级一阶滤波，4096 样本归一化，xorshift 种子（默认 `123456789`），跑在 AudioWorklet 里。

> 这一段对我们特别有用：`音色引擎-分析.md` §4.5 的程序化 IR、§4.3 的压缩器参数都是自拟的；参考产品给出了「磁带味 = 高频搁架衰减 + 15.5k 低通 + -54dB 带限噪声」这套更轻的方案，可作为 `chip` / `warm` 预设的另一种取值来源。

### 6.3 频谱分频（10 段，几何平均）

中心频率：**63, 125, 250, 500, 1K, 2K, 4K, 8K, 12K, 16K**（标准倍频程 + 12k/16k 收尾）。

- 段边界用**相邻中心频率的几何平均**（`sqrt(f_prev * f)`），首尾按比例外推；
- 每段取该频率区间内 FFT bin 的**最大值**，再映射为 **0–10 档**（`min(10, max/25.5)`）；
- 10 档正好对应每列 10 颗 LED。

**与我们方案的差异**：`点阵与辉光-动效方案.md` 用 22 列 × 14 行、按 `t^1.85` 对数取样；参考实现是 **10 段固定倍频程 + 每段 10 档**。两者不是谁对谁错 —— 10 段是「硬件 LED 频谱」的做法，22 列是「点阵屏」的做法，可以并存为两个渲染器。

### 6.4 LED 的两种画法

| 场景 | 画法 | 颜色 |
|---|---|---|
| 真实版 deck（CSS） | 100 个 `i`，每颗 4px，`on` 类点亮 | 橙 `#e8973d` / 高位红 `#de4b2f` |
| HUD 模式（Canvas） | 离屏预渲染发光贴图 + `drawImage` | 4 段：红 `#ff354a` → 黄 `#ffcf32` → 绿 `#4bea70` → 蓝 `#348fff`，按高度 0.24/0.46/0.64 分界 |

**这条验证了 `点阵与辉光-动效方案.md` §5 的性能判断**：参考实现同样用「预渲染贴图」而不是逐点 `shadowBlur`，且面板底色是 `#17110d → #3a291b → #130d0a` 的深色渐变 + 每 8px 一条扫描线。

### 6.5 VU 的真相

- 早期版本（`index.html`）的 VU 是 **`Math.random()` 驱动**，与音频无关；
- 当前真实版的 `rpVuL/rpVuR` 只在**电源开关时**做一次 5° 摆动动画（电源瞬态），不是实时电平；
- HUD 模式提供「双指针 VU」，但数据来自同一 analyser 的 RMS。

→ **参考产品的 VU 在主力界面基本是装饰**。我们在 `实现路径.md` §6 要求「真实 RMS + 峰值保持」比它更诚实，不必为了「像」而改成随机。

## 8. 局限与未验证项

1. **语义图是 partial**：REA 的 data-flow 关系被 100k 节点上限截断，`unknown` 关系 42,635 条；结论以「读到的代码」为准，不能宣称穷尽。
2. **preload 入口识别为 0**：`electron-main.js` 用动态路径加载 `preload.js`，REA 未建立入口关系；但 `preload.js` 本体存在且已读到 13 个桥 / 57 个成员。
3. **没有动态验证（已决定不做）**：全程静态分析，未启动应用、未抓运行时参数；走带转速、翻面时长来自代码常量，未做帧级实测。
   - **2026-11-04 决定**：不补动态抓取。理由是 Re:Play 为 Electron、业务代码可读，上表参数均为**源码常量**（精度高于像素反推）；而动态抓取唯一能补的三项 —— 合成后的屏幕色、LED 离屏贴图的模糊参数、动效手感 —— **都不在 `播放器改造方案-v2` 的验收项内**（该方案已定「形似 + 真实数据，不做照片级还原」）。
   - 保留的触发条件：若将来要做「与参考并排的视觉验收比对」，再抓 4 张基准图（静止 / 播放 / 快进 / LED 特写）即可，用现成的 `PrintWindow` 管线，约 10 分钟；截图只留 `.workbuddy/`，不进仓库。
   - 另：登录门槛只存在于 `cabinet-commerce.js` 与 `cabinet-workspace.js`（商城、工作区），播放器本身不需要登录 —— 也就是说这个决定不是因为「抓不到」，而是「不需要」。
4. **版本单一**：只分析了 0.7.6（2026-09-30 构建）；旧版本行为可能不同。
5. **VU 是否真的「全装饰」**：主力界面如此，但 HUD 的 VU 模式读取 analyser，若后续要抄它的表盘刻度，需要动态确认。
6. **字体与位图**：卡带照片、场景图、字体均为对方素材，**不可复制**；本文只给坐标与数值，落地时必须自己用 SVG/CSS 重绘。

## 9. 对 deck 方案的三条修订建议

1. **卷盘数学换成平方根模型**：`实现路径.md` §6 的 `rMin=0.55 / rMax=1.0` 线性插值改为 `sqrt(1-0.72p)` / `sqrt(0.28+0.72p)`，并把角速度改成 `v/h`（v=1.5/10/-10，τ=1/9s）。观感会明显更像真机。
2. **频谱渲染器增加「10 段 LED」档**：`点阵与辉光-动效方案.md` §9.2 已经设计了 `VIZ.setRenderer('dots'|'bars')`，可再加 `'led10'`，直接用 63…16k 几何平均 + 10 档映射，作为 Deck 皮肤的仪表盘；极光仍用点阵。
3. **`warm` 预设参考磁带染色**：`AI母带-方案.md` §5 的 `warm` 目前只有 EQ 曲线，可叠加「shelf 4500Hz -2dB + LPF 15.5kHz + -54dB 噪声」这一组轻量染色，比纯 EQ 更接近「磁带味」。
