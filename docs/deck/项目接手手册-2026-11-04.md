## 3. 产品是什么 / 这次要做什么

RetroMusicLab（README 标题 `RetroMusic Lab · MSU1Converter`）：把 30 多个机种的游戏音乐转成可听音频 / 可烧 CD。
Windows 桌面工具，Python 3.14，Web UI 试听台（`web_ui/`），6 套复古浅色主题，**仓库坚持 0 位图**（CSS 渐变 + inline SVG）。

本次改造范围（已收敛）：

- 两种播放风格二选一：**Deck**（横向磁带机 ≈2.4:1）/ **极光**（竖向前封面 + 右侧声音面板）；
- **音色引擎**：Web Audio DSP 链 + 6 预设 + 9 段 EQ + 4 开关；
- **AI 母带**：按当前音源的客观频谱自动匹配音色曲线；
- 只做播放器功能。**不做**歌词（含元数据跑马灯）、电台、AI 懂你 / 推荐 / 歌单、账户 / 积分 / 商城。

## 4. 已拍板的决策（不要再讨论）

| 决策 | 结论 | 出处 |
|---|---|---|
| 承载方式 | **PlayerView 覆盖中间栏 `stage`**，dock 仍是迷你条；两风格是同一 PlayerView 的两个渲染器 | 双风格 §4 |
| 缩放 | `aspect-ratio` + 百分比绝对定位，**不用** `transform: scale()` | 交接 §7 |
| dock / 左栏尺寸 | **86px / 260px**（232 是 dock 自己第一列，不是左栏） | 交接 §5-4（实测 `app.css:142/229/958`） |
| EQ 段数 | **9 段，±6dB**（AI 侧 `presetBands` ±4dB），不是 3 段 | 音色引擎 §11 |
| AI 边界 | AI **只给音色曲线**；4 开关 + 9 段 EQ + 音量全归用户；`/api/tone` **刻意不返回 `flags`** | AI母带 §0/§3 |
| 两层 EQ | `实际应用 = clamp(presetBands + userBands, -6, +6)`，手动值永久保留 | AI母带 §2 |
| 音色引擎归属 | 进**内核** `Core.tone`，不进皮肤；切皮肤音色不丢、不重算、不爆音 | 音色引擎 §8 |
| 音量口径 | `audio.volume = 1.0` 钉死，音量交给 `outGain`；同步改 `download.js:391` 旧注释 | 交接 §5-2 |
| 采样率 | 界面写 **44100**（产物格式，`OUT_RATE`）；生成 IR 用 `ctx.sampleRate`，不写死 | 交接 §5-3 |
| rAF 语义 | `V.on` 只决定「画不画 canvas」，**不决定跑不跑循环**；统一调度器合并现有 3 条 rAF | 交接 §5-6 / 音色曲线 §7 |
| 曲线载体 | **SVG `<path>`** + `getFrequencyResponse` 真实响应，不是示意图 | 音色曲线 §0–§2 |
| 点阵面板 | **永远是深色显示屏**，浅色主题里是嵌进界面的深屏；不跟着变浅 | 点阵 §9.3 |
| 频谱灯光 | **完全不跟 6 套全局主题**（4 灯 × 6 主题 = 24 组映射且必然难看） | 交接 §6 |
| 试听 vs 导出 | **试听侧所有处理都不影响导出 WAV**，导出全在 Python 侧 | 交接 §5-10 |
| 输出设备 | 有条件可做：`AudioContext.setSinkId()`（Chromium 110+），只能按序号显示 | 音色引擎 §4.7 |
| 默认皮肤 | `deck`（存 `rml-player-skin`） | 双风格 §6 |
| 不做 | 歌词 / 跑马灯 / 电台 / 推荐 / 账户 / 商城 / 极光要「AI 懂你」 | AI母带 §1 |

**已被推翻的旧结论（别按这些做）**：dock 展开就够、72px/232px、`transform: scale`、9 段降 3 段、

## 6. 架构与皮肤契约

```js
Core.state  = { skin, playing, id, name, fmt, sr, bits, br, dur, pos, volume, eq, live }
Core.audio / Core.viz            // 单例只读引用
Core.on("state" | "frame" | "track", cb)
Core.play() / pause() / seek() / setVolume() / setSkin()
Core.tone   = { preset, bands[9], flags{master,space,dyn,loud}, volume }
Core.setPreset / setBand / setFlag / setVolume / analyze()

Skin = { id, label, mount(host, core), unmount(), resize(), onState(s), params: [...] }
```

**四条不变量（写进注释，也写进机械检查）**：

1. 皮肤不碰音频：`grep "createMediaElementSource\|AudioContext" skin_*.js` 必须为空；
2. 皮肤不建 DSP 节点：`grep "createBiquadFilter\|createDynamicsCompressor\|createGain\|createConvolver" skin_*.js` 必须为空；
3. 皮肤不直接写 `param.value`，只能调 `Core.set*()`；
4. 皮肤不写 `localStorage`、不发网络请求（皮肤选择由 core 存 `rml-player-skin`）。

补充：`双风格-可行性分析.md` §5 的三条是「不 connect / 不写 localStorage / 不发请求」，
与 `音色引擎-分析.md` §8 的第 4 条合并后共 4 类约束，按更严的执行。
