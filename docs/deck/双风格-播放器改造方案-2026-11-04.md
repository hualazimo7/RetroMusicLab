# RML 播放器双风格改造方案

- **版本**：2026-11-04
- **范围**：转换页 `index.html` 与音源下载页 `download.html` 各自的播放器，统一为一个可换肤组件
- **不涉及**：转换/下载业务逻辑、跨页连续播放、更换外壳
- **取代**：`双风格-可行性分析.md` §4 的承载结论（该文按「单页 + dock 展开」推演，前提已变）

---

## 0. 结论摘要

1. 两页各有一个**独立播放器**（两个 `new Audio()`），本次合并为**一个组件 `PlayerView`**，仍挂在两页原位置，不搬动既有栅格。
2. 皮肤是**全局偏好**（Deck / 极光），任选，一次切换两页同时生效，存 `rml-player-skin`。
3. 真正的难点不是美术，而是**容器形状错位**：转换页是「全宽 × 86px」的横条，下载页是「356px × 约 300」的窄栏；而 Deck 偏好宽、极光偏好高。解法是**每套皮肤各做两档形态**，由**容器尺寸**驱动，而不是按页面绑定皮肤。
4. 参数不再现场测量：Deck 用 Re:Play 的源码常量，极光用 AURORA 的像素实测，两套都已落盘（见 §7）。
5. 三条硬约束：**机身内缩 8–12px**、**一屏一处 blur**、**皮肤不得碰音频图**。

### 0.1 已拍板（2026-11-04）

| 编号 | 决定 | 影响 |
|---|---|---|
| D1 | 转换页 dock **提高**（取值与 D4 绑定，建议 200px） | `app.css` 行高由 `50/1fr/86` 改为 `50/1fr/<H>`；表格区相应减少 |
| D2 | **两页都给「上一首 / 下一首」** | `caps.prevNext` 两页均为 true；Source 必须提供有序清单与当前索引 |
| D3 | 失效态**只做提示 + 回列表** | 不做「重新定位」；文案与动作见 §6.2 |
| D4 | 极光必须有**音色点阵**；dock 定为 **200px**、点间距 **11px** | 点阵 **286×176**；占宽约 1/5；转换页表格仍余约 700px |
| D5 | **保留 48 柱**，做成极光皮肤内的渲染选项（默认点阵） | 极光多一个 `dots / bars` 切换（`rml-player-viz`）；现有 48 柱 + 波形代码不删，降级为可选路径；详见 §5.3.2 |

> D4 的结论改变了 §5.2 的原设计：极光在 compact 态**保留点阵**，只是缩小，不做频谱带替代。

## 3. 核心矛盾与解法

### 3.1 错位矩阵

| | 需要什么 | 转换页 全宽×86px | 下载页 356×300 |
|---|---|---|---|
| **Deck** | 横向 ≈2.4:1，200–300px 高 | 高度不够 | 宽度不够 |
| **极光** | 竖向，低于 480px 会挤成一团（`双风格-可行性分析.md` §4 已论证） | 完全不够 | 高度不够 |

结论：**没有任何一个皮肤在两种容器里都能用同一套布局**。所以"每套皮肤一套布局"这个前提不成立。

### 3.2 解法：两套皮肤 × 按容器尺寸切形态

不用「按页面选皮肤」，而是让皮肤根据**容器实际尺寸**切换形态（CSS 容器查询 `container-type: size`）。

**两个独立的轴**，分别判：

| 轴 | 判据 | 取值 |
|---|---|---|
| **方向** | 宽 / 高 ≥ 4 → 横条；≤ 2 → 竖栏；之间 → 中性 | `wide` / `narrow` / `mid` |
| **点阵间距** | 由容器可用高与宽共同约束（取两个方向的较小值） | 15 / 11 / 8 / 6px |

两页实际命中：

| 页面 | 容器 | 宽高比 | 方向 | 点阵间距 |
|---|---|---|---|---|
| 转换页（dock 提到 200） | 全宽 × 200 | ~8 | **wide** | **11px**（点阵 286×176） |
| 下载页 | 356 × 约 300 | ~1.2 | **narrow** | **10px**（宽度反推上限 12.5，留余量） |

**为什么不用「高度 200 一刀切」**：dock 200px 与下载栏 300px 只差 100px，用高度区分会让 200px 的横条被误判成竖栏布局。用**宽高比**判方向更稳，而点阵尺寸单独由可用空间算——两个轴各管一件事，互不干扰。

每种皮肤只需写 2 套布局（wide / narrow），点阵/meter 尺寸由 CSS 变量跟着档位走。**2 套皮肤 × 2 方向 = 4 个布局，不是 8 个。**

### 3.3 dock 高度：由点阵尺寸反推，不是拍脑袋

D4 要求极光**保留音色点阵**，所以 dock 高度不再由"控制条多高"决定，而由"点阵能缩到多小还认得出"反推。

**关键前提**：AURORA 的 31.5px 点间距是它在 **2125px 窗口**下的绝对值，不是设计常量。我们的容器更小，点阵等比缩即可，26 列 × 16 行的结构完全保得住。

| dock 高 | 可用点阵高 | 点间距 | 点径 | 点阵实际尺寸 | 观感 |
|---|---|---|---|---|---|
| 120px | 96 | 6px | 5px | 156 × 96 | 认得出是点阵，但很小 |
| 160px | 136 | 8px | 7px | 208 × 136 | 小，结构清楚 |
| **200px** | 176 | **11px** | **9px** | **286 × 176** | **结构完整，16 行分段可辨** |
| 280px | 250 | 15px | 13px | 390 × 240 | 可当主视觉，但表格被压 |

**决定（2026-11-04 22:58）：取 200px + 11px 间距**，点阵 286×176，理由：

- 点阵 286px 宽在横条里只占约 1/5，"左点阵 + 中信息 + 右控制"排布舒适；
- 比 AURORA 原版"点阵铺满面板"更像真实设备上的小屏，**横条反而成为优势**；
- 中间栏表格少 114px，1080p 下仍余约 700px 可用。

若后续觉得表格被压，可降到 160px（点阵 208×136），仍能看出 16 行分段；低于 120px 不建议，那时点阵只剩 6 行，分段信息会丢。

**实现方式**：点阵不占满全宽，按固定尺寸居中在左侧槽位；`--dot-pitch` 用 CSS 变量，按形态档位切换（11px / 8px / 6px），**列数行数永远 26×16**，只改间距。

## 4. 架构

### 4.1 分层

```
页面（index.html / download.html）
   └─ PlayerView（容器，只管尺寸与挂载）
        ├─ PlayerCore   ← 唯一状态源：播放/进度/音量/曲目
        ├─ PlayerSource ← 数据适配器（转换页 / 下载页各一个）
        └─ Skin         ← deck | aurora，只读状态、只画
```

### 4.2 契约

```js
/* player_core.js —— 只有一份 */
Core.state = {
  skin: "deck",                 // 读 rml-player-skin
  playing, id, name, sub,       // 曲目
  dur, pos, volume,             // 时长/进度/音量（dur 可能为 0，见 §6.4）
  live: false,                  // 分析器是否有有效数据
  status: "ok" | "missing",     // 失效态（见 §6.2）
  caps: { prevNext: true, covers: false },  // 能力位，由 Source 声明
  canPrev: false, canNext: false,  // 边界状态，由 core 算好（见 §6.1.1）
  cover: { game, n, idx, url } | null,  // 封面（见 §5.3.3），无封面源时为 null
  empty: false                  // 列表为空
};

Core.audio   // 单例 <audio>，只读引用
Core.viz     // VizKit 实例，只读引用
Core.on("state" | "frame" | "track", cb)
Core.play() / pause() / toggle() / seek(pos) / prev() / next()
Core.setVolume(v) / setSkin(id)

/* 皮肤契约 */
Skin = {
  id: "deck" | "aurora",
  label: "磁带机" | "极光",
  mount(host, core),   // 建 DOM；只能通过 core 拿数据
  unmount(),           // 解绑、停自己的 rAF
  resize(w, h),        // 由 ResizeObserver 转发（形态切换也可纯 CSS 完成）
  onState(s)
}
```

### 4.3 五条不变量（写进注释，也写进验收）

1. 皮肤**不得**碰 `core.audio` / `core.viz` 的节点图（不 `connect`、不 `createMediaElementSource`）——否则会重演 `viz.js` 那三条坑，症状是「频谱漂亮但没声音」；
2. 皮肤**不得**写 `localStorage`，皮肤选择与音量都由 core 统一存；
3. 皮肤**不得**发网络请求——数据全部从 `Core.state` 来；
4. 皮肤**不得**直接查询页面上的业务 DOM（如表格行），只认 `Core.state`；
5. 皮肤**不得**假设容器尺寸——所有布局必须由容器查询或 `resize()` 驱动，不能写死像素宽度。

## 5. 两套皮肤规格

### 5.1 Deck（磁带机）

| 形态 | 布局 | 关键尺寸 |
|---|---|---|
| `wide`（转换页） | 走带条：左卷盘（一对）· 中进度与时间码 · 右音量 | 容器高 200；卷盘 72–88 |
| `narrow`（下载页） | 竖置卡座：上卡带窗（双轮毂并排）· 中标签与信息 · 下控制与进度 | 容器宽 356；轮毂 100–120；高 ≥ 300 |

参数全部来自 Re:Play 源码常量（见 §7.1），要点：

- 卷盘半径用**平方根模型** `sqrt(1-0.72p)` / `sqrt(0.28+0.72p)`，不是线性插值；
- 角速度 = 线速度 / 半径，`v = 1.5 / 10 / -10`，一阶平滑 `τ ≈ 1/9 s`；
- 进度为 0 时两盘等半径，为 1 时一盘满一盘空；
- 底部电平用 **10 段 LED**（63…16k 几何平均 + `min(10, max/25.5)`），配色见 §7.3。

### 5.2 极光（面板）

| 形态 | 布局 | 关键尺寸 |
|---|---|---|
| `wide`（转换页） | **缩尺点阵**：左槽 26×16 点阵 + 中信息 + 右控制 | 容器高 200；`--dot-pitch: 11px`；点阵 286×176 |
| `narrow`（下载页） | **面板**：26×16 点阵 + 氛围环 + 曲线 + 控制 | 容器宽 356；`--dot-pitch: 10px`；每列约 12.5px |

参数来自 AURORA 像素实测（见 §7.2），要点：

- 点阵**永远 26 列 × 16 行**，任何形态都不改行列数，只改 `--dot-pitch`（11px / 8px / 6px）；
- 四段色分界 **0.20 / 0.40 / 0.70**（等价 10 级电平 2/4/7），与 Deck 的 LED 共用同一份分级；
- 氛围环是**面板周界描边**，不是外溢光；单色档为单色，彩虹档为周长参数化渐变；
- 四档动态：静态（不动）/ 呼吸（3.6 s）/ 律动（音频包络，只调亮度不动色相）/ 环绕（沿周界行波 2.0 s）。

**D4 的取舍已定：compact 态保留点阵，不做频谱带替代。** 理由：音色点阵是这一风格的识别特征，换成柱状频谱带就变成"另一种可视化"了；缩到 11px 间距后，16 行的分段仍可辨，结构没丢。代价是 dock 必须给到 200px（见 §3.3）。

### 5.3 内容层：频谱与封面

这两块是**现有功能**，不是新做的，所以要先说清迁移路径。

#### 5.3.1 频谱：`viz.js` 保留「算」，皮肤接管「画」

**现状**（`viz.js`，两页共用，`app.js:510` / `download.js:378`）：

| 项 | 现值 |
|---|---|
| 渲染 | **48 根柱**（`NBARS` 默认 48，可调 16–96）+ 峰值保持 + 叠加波形线 |
| 频段映射 | `bin = floor(pow(t, 1.85) * freq.length * 0.62)`，`t = i/(NBARS-1)` |
| 幅度整形 | `v = pow(v, 0.72)` —— 抬低幅，安静段不至于贴地 |
| 其他 | 主题色跟随（每 500ms）、dpr 适配、空态、开关、rAF |

两页共用这一点很关键：注释里已经写了「下载页也要同一块面板，各写一份迟早不一致」——**跟本次改造是同一个判断**，所以 VizKit 不重写，只拆职责。

| 留在 VizKit（不动） | 交出去给皮肤 |
|---|---|
| AnalyserNode 生命周期、FFT、`getByteFrequencyData` | 柱宽、间距、圆角、配色 |
| 频率映射公式、幅度整形 | 画多大的点阵、画在哪个槽位 |
| 峰值保持缓冲区、空态、开关、主题色、dpr | 波形线是否叠加、叠加在哪 |

新增契约：

```js
viz.frame() → {
  bands: Float32Array,   // 长度 = 目标列数（10 / 26 / 48）
  wave:  Uint8Array,     // 时域，长度 = fftSize
  rms:   number          // 0..1
}
```

**三个必须注意的坑**（都是改根数时会踩的，不是理论风险）：

1. **`0.62` 不是常数**。`pow(t,1.85) * freq.length * 0.62` 里，0.62 是为 48 根调的频带上限；直接把 `bars` 改成 10 或 26，同一公式只覆盖 62% 的频带，**顶部 38% 的高频永远取不到**。换根数必须同步重算上限系数（目标应是 1.0），并复核幂次。
2. **`pow(v, 0.72)` 对 LED 有害**。它是为 HUD 观感抬低幅；10 段 LED 是硬阈值器件，抬了之后安静段落会整排亮。**LED 路径必须关掉这步**（或改用阈值 + 迟滞）。
3. **峰值保持的数组长度**。现在是「每根柱子一条」，点阵形态下要改成「每列一条」，不能直接复用长度为 48 的数组。

**渲染归属**：

| 皮肤 / 形态 | 频谱部分 | 波形层 |
|---|---|---|
| Deck wide | **10 段 LED**（横排） | 可叠，画在两卷之间那条"磁带面"上 |
| Deck narrow | **10 段 LED**（竖排） | 同上 |
| 极光 wide | **26×16 点阵**（默认）/ 48 柱（可选） | 叠在点阵下沿 |
| 极光 narrow | 同上 | 同上 |

**波形的定位**：它是**诊断工具**不是装饰 —— 转换工具要靠它看削波、看静音段、看转出来的东西对不对。所以它跟柱状/点阵是**正交**的：`bands` 归皮肤画，`wave` 两套皮肤都可以叠一层。这也是「48 柱可以退役、波形必须留」的理由。

#### 5.3.2 极光的渲染选项（D5）

| 项 | 值 |
|---|---|
| 选项 | `点阵`（默认）/ `柱状` |
| 存储 | `rml-player-viz`，值 `dots` \| `bars` |
| 生效范围 | **仅极光皮肤**；切到 Deck 时该值保留但不生效 |
| 切换行为 | 即时生效，**不重建 AnalyserNode**（只换绘制路径） |
| 入口 | 极光面板上的一个小图标切换（不进设置页，避免为一项设置多开一层） |

「柱状」复用的是现有 48 柱 + 波形实现，代码不删，只是从"唯一渲染"变成"极光的可选项"。

#### 5.3.3 封面轮播：定时器必须归内核

**现状**（`download.js:669-760`，仅下载页）：

| 细节 | 现值 |
|---|---|
| 间隔 | **3 秒一张**（`COVER_EVERY_MS`） |
| 前提 | `coverN ≥ 2` **且 `audio.paused` 时不转** |
| 同游戏连播 | **不重置**索引（靠 `S.coverGame` 判断） |
| 加载失败 | `onerror` 自动试下一张；全失败才显示占位，**不弹 toast** |
| 折叠 | 用户可收起封面区，状态记在 `msu1.dl.cover.fold` |
| 数据源 | `/api/dl/covers?game=` 取张数，`/api/dl/cover?game=&i=N` 取图 |

**如果让两个皮肤各写一份轮播**：切皮肤时索引各走各的，封面会跳一张；而且每 3 秒会发**两次** `/api/dl/cover` 请求。

所以：**定时器只有一个，放在 core**。

```js
Core.state.cover = { game, n, idx, url }   // url 由 core 拼好，皮肤直接用
Core.nextCover()                            // 内部 3s 定时；暂停时不动
```

**转换页没有封面数据源**——`server.py` 的 `covers` / `cover` 只挂在 `/api/dl/` 分支下（走 `dl_state().cover_paths(game)`），转换页的输出没有游戏归属。所以：

- `caps.covers: false` → 两套皮肤都走**程序化封面**（渐变 + 曲名首字），**不能空着**；
- "封面轮播"在转换页天然不存在，不是缺失。

**位置（2026-11-04 P0′ 实测修正）**：封面**不进播放器**。

原计划是「极光 narrow 顶部 120×120、Deck 标签 56×56」，实机一测就崩：356×300 的容器里塞不下「120 封面 + 16 行点阵 + 信息 + 控件」，`main` 和 `ctrl` 被挤到可视区外。而且下载页本身已有独立封面区（`#dlCoverBox`），再做一份是重复。

改为：

| | 谁画 | 说明 |
|---|---|---|
| 下载页封面 | **页面**（沿用 `#dlCoverBox`） | 订阅 `Core.state.cover` 渲染，定时器仍归 core |
| 转换页 | 无封面 | 没有封面源，也不需要占位 |
| 播放器内 | **不画封面** | 只负责传输与仪表 |

这样既解决溢出，也避免两处封面各自轮播。Deck 的卡带标签保留一条**条纹贴纸**表达"盘里有内容"，不画图。

## 6. 数据契约与边界情况

### 6.1 两个 Source 适配器

```js
/* 转换页 */
ConverterSource = {
  list:  () => state.outputs,          // 会话内输出登记表，按转换顺序
  urlOf: it => "/api/audio?id=" + it.id,
  keyOf: it => "id:" + it.id,
  resume: "session",                   // 重启程序即失效
  caps: { prevNext: true, covers: false }   // 转换页没有封面接口（见 §5.3.3）
}

/* 下载页 */
DownloadSource = {
  list:  () => dlState.visibleRows,     // 当前列表（含搜索/筛选结果）
  urlOf: it => "/api/dl/audio?rel=" + encodeURIComponent(it.rel),
  keyOf: it => "rel:" + it.rel,
  resume: "persistent",
  caps: { prevNext: true, covers: true },
  coverApi: {                          // 只有声明了 covers 的 Source 才需要
    count: g => "/api/dl/covers?game=" + encodeURIComponent(g),
    url:   (g, i) => "/api/dl/cover?game=" + encodeURIComponent(g) + "&i=" + i
  }
}
```

皮肤永远不知道背后是 id 还是路径。

### 6.1.1 上一首 / 下一首的行为（D2 定了才需要写清）

| 项 | 规则 |
|---|---|
| 顺序来源 | 转换页 = 输出登记表的顺序（即转换顺序）；下载页 = **当前可见列表**的顺序（含搜索/筛选后的结果，不是全库） |
| 首尾 | **不循环**。第一首时 `prev` 禁用，最后一首时 `next` 禁用 |
| 列表为空 | 两键都禁用，播放器显示空态 |
| 切歌方式 | 直接跳转并播放（与现有两页的点击行为一致），不做淡入淡出 |
| 与皮肤的关系 | 皮肤只渲染 `caps.prevNext` 与 `state.canPrev/canNext`，不自己算索引 |

### 6.2 失效态（D3：只做提示 + 回列表）

- 转换页：id 在会话内有效，**重启程序后 404**；
- 下载页：文件可能被用户手动删掉。

`status: "missing"` 时的表现，两套皮肤一致：

1. 面板显示「文件已不在了」+ 原曲名（灰化）；
2. 传输键全部禁用，只留一个「回列表」动作；
3. 点「回列表」→ core 发 `Core.clear()`（清空当前曲目、停播），**页面自己**负责滚动并高亮列表位置。

**边界**：皮肤**不得**直接操作列表 DOM（不变量 4），所以"回列表"只能发事件，滚动与高亮由页面侧实现。这是 D3 唯一的实现约束。

不做「重新定位」（不在 D3 范围内）。

### 6.3 恢复策略

| 页面 | 切页回来 | 重启程序 |
|---|---|---|
| 转换页 | 恢复上次曲目（id 仍有效） | 清空 |
| 下载页 | 恢复上次曲目 | 恢复（rel 持久） |

### 6.4 时长缺失

Deck 的卷盘依赖 `dur`。若某条目读不到时长：

- 卷盘**静止在"两盘等半径"的中性位置**，不做假转速；
- 进度条切到「不确定」样式；
- 绝不除以 0。

### 6.5 列表规模

下载页可能几百条。**播放器面板只管"当前这一首"**，列表留在页面原处（`#dlPlayList` / 主表格），从根上避免皮肤渲染大列表。

## 8. 外壳（Edge `--app`）的适配结论

现状：`shell.py` 用系统 Edge 的 `--app` 模式（Chromium 应用窗口），降级链 Edge → Chrome → Brave → Vivaldi，独立 `--user-data-dir`，47913 端口兼作单实例锁。**不是 WebView2 嵌入式**（docstring 记录 pywebview 在本机跑不起来）。

| 维度 | 判定 | 说明 |
|---|---|---|
| 渲染能力 | ✅ 够 | container queries / `:has()` / Web Audio / OffscreenCanvas / canvas 60fps 都是 Chromium 原生 |
| 尺寸响应 | ✅ 够 | 页面内 `ResizeObserver` 即可，不依赖外壳 |
| 偏好持久化 | ✅ 好 | 独立 profile，不被用户清理浏览器影响 |
| 进程隔离 | ✅ 好 | 渲染崩了不拖垮 Python 服务端 |
| 大面积毛玻璃 | ⚠️ 限流 | 点阵 + 氛围环 + `backdrop-filter` 三重叠加会掉帧 → **一屏只允许一处大面积 blur** |
| CSS 版本 | ⚠️ 兜底 | container queries 需 Chrome 105+；降级链里可能有旧内核 → 关键布局配 `@supports` |
| 启动延迟 | ⚠️ 注意 | 拉起 Edge + 端口探测约 1–2 秒 → **不做开机动效** |
| 无边框 | ❌ 不做 | `--app` 窗口仍有系统边框与 Edge 图标；去边框需自实现拖动/缩放，且 Chromium 窗口不支持 `-webkit-app-region: drag`，Edge 更新还可能失效 |

**两条设计约束**：

1. **机身内缩 8–12px**：圆角与内阴影画在页面内，不贴窗口边缘，否则会被系统框切掉；
2. **窗口即机身做不到**，只能做「窗口里的机身」。想要整机感唯一干净的路是换壳，本轮不做。

## 15. P1 交付记录：Deck 的走带物理（2026-11-04 23:4x）

### 15.1 做了什么

P0′ 的卷盘只是一个**匀速 CSS 动画**（`@keyframes spin 2.6s/3.4s`），转得像装饰。
P1 换成真走带：盘径随进度变化、两盘角速度不同、起停有惯性。

| 文件 | 行数 | 说明 |
|---|---|---|
| `player/deck_physics.js` | ~125 | **纯函数**：半径模型、平滑、角速度、单帧演进。无 DOM、无状态 |
| `player/deck_physics.test.js` | ~95 | 单测，`node` 直接跑，**242 条断言** |
| `player/skin_deck.js` | ~150 | rAF 驱动：读 state → 算盘径与角度 → 写两个 CSS 变量 |
| `player/skin_deck.css` | ~175 | 四层卷盘结构（井 / 旋转层 / 带盘 / 轮毂）+ 绕带层纹 |

### 15.2 参数与来源

全部照 Re:Play 的 `cassette_motion` 实现（`replay-逆向分析` §5.2–§5.3），不是估算：

```js
hL = sqrt(1 - 0.72 * p)          // p = pos / dur，夹在 0..1
hR = sqrt(0.28 + 0.72 * p)
ω  = v / h                       // v: 播放 1.5、快进 10、倒带 -10、暂停 0
k  = 1 - exp(-dt * 9)            // 一阶平滑，τ ≈ 111ms
angle += ω * dt                  // 取模 2π
```

| 端 | 左盘 | 右盘 | 比例 |
|---|---|---|---|
| `p=0` | 1.000 | 0.529 | 左满右空 |
| `p=0.5` | 0.800 | 0.800 | 两盘相等 |
| `p=1` | 0.529 | 1.000 | 左空右满 |

**自洽性**：`hL² + hR² = 1.28` 恒定（1 是满盘面积，0.28 是小盘保底面积）。
这条比「三点拟合」更能说明模型是对的，已写成单测断言。

### 15.3 四个必须记下的实现细节

1. **缓动不能放在 CSS 里**。两个盘角速度不同（同线速度、不同半径），
   而且每帧都要跟着进度改盘径 —— CSS 只能给固定周期，做不到。
   所以整段交给 rAF，每帧只写 `--r` / `--a` 两个自定义属性。
2. **`dt` 必须夹到 0.08s**。切标签页回来时 `dt` 可能是几秒，
   不夹的话一帧转过一整圈，画面直接「闪现」。
3. **盘面纹理必须旋转对称**。第一版在带盘上放了偏心高光（`circle at 42% 36%`），
   一转就像有束光跟着盘走，很假。改成同心绕带层纹 + 居中的径向渐变。
4. **井口高光单独一层**（`.dk-reel::after`），不跟着转 —— 光不会转。

### 15.5 两条容易被做错的物理常识

- **两个卷盘转向相同**，不是相反。磁带是一个闭环：底边那一截朝一个方向走时，
  两个盘的底面都朝同一边移动，所以角速度同号。第一直觉「一收一放应该反向」是错的，
  Re:Play 的实现也是同号。
- **空盘转得快**。同一个线速度下 `ω ∝ 1/r`，播放到尾部时左盘半径只剩 0.53，
  角速度是满盘时的 1.89 倍。这也是「看起来转得对」的关键 ——
  恒定转速反而一眼假。

### 15.6 还没接的：快进 / 倒带

`deck_physics` 里 `SPEED.ff = 10`、`SPEED.rew = -10` 已经就位，但**界面还没有
快进/倒带键**，所以 `skin_deck._frame()` 目前只在 1.5 与 0 之间切换。
将来加这两颗键时，只需把 `speed` 那一行改成按状态取值，物理部分不用动。

**没有用「拖动进度条时推断快进」的做法**：`v` 是磁带线速度、`p` 是音频时间进度，
两者量纲不同（Re:Play 里也是解耦的），拿 `Δp/Δt` 反推 `v` 会得到一个假比例。

### 15.7 测试环境的一个坑

用 `page.route` 伪造 `/api/dl/audio` 时**必须带 `Accept-Ranges: bytes`**，
否则 Chromium 认为该资源不可 seek，`seek()` 静默失效、进度永远停在 0
（真实后端 `_send_wav` 是支持 Range 的，206 + Content-Range）。

## 16. P2 交付记录：极光的真实频谱（2026-11-04 23:5x）

### 16.1 一句话

P0′ 的极光是一张 CSS 画的静态网格；P2 换成 **canvas + 真实频谱**，
并把「分频」与「分级上色」拆成可单测的纯逻辑。

| 文件 | 行数 | 职责 |
|---|---|---|
| `player/level_scale.js` | ~110 | **纯函数**：网格常量、四段分界、电平→行数、两套配色 |

| `player/skin_aurora.js` | ~200 | canvas 渲染（dots / bars）、切换键、离屏暗点层 |
| `player_core.spectrum(cols)` | ~30 | 按 **Hz** 分段的频谱，返回 0..1 数组 |

### 16.2 分析节点归谁：只能有一个

`createMediaElementSource()` 对同一个 `<audio>` **只能调一次**，第二次抛
`InvalidStateError`。所以不能让内核和 VizKit 各建一个 —— 那会把声音搞没。

做法：**VizKit 建、内核借用**。`viz.js` 在 `ensure()` 里建好 analyser 后调
`PlayerCore.attachAnalyser(an, ctx)`；内核只保存引用，永不重复创建。
两页都是「用户第一次点播放」这个手势里建图，时序天然对。

### 16.3 分频：把 0.62 这个魔法系数彻底去掉

`viz.js` 的老公式是 `pow(t, 1.85) * freq.length * 0.62`。那个 `0.62` 是为
**48 根柱**调的频带上限系数 —— 把柱数改成 26 之后，顶上 38% 的频带
永远取不到，而且肉眼看不出来（`§5.3.1` 记过这个坑）。

P2 改成**按频率分段**，不依赖柱数：

```
第 i 段 = [60 * (16000/60)^(i/26), 60 * (16000/60)^((i+1)/26)] Hz
段内取 bin 最大值 → /255 → 0..1
```

没有系数可忘，段数怎么变都成立。**验证**：1 kHz 单音落在第 13 列
（解析解 13.09），8 kHz 落在第 22 列（解析解 22.77），实测峰值列完全一致。

另外**不加 `pow(v, 0.72)`**：那是给柱状图「抬低幅」用的视觉效果，
点阵是硬阈值显示，抬了低幅会让安静段落整排亮起来。

### 16.4 分级与配色：分界不是四等分

实测换色落在自底向上的第 3 / 6 / 11 行，归一化后是 **0.20 / 0.40 / 0.70**
（等价于 10 级电平在 2/4/7 级换色）。写成 0.25/0.50/0.75 会让第 4、8 行换色，
一眼能看出「颜色分层不对」。

| 段 | 行（16 行制） | 复古四色 | 赛博朋克 |
|---|---|---|---|
| 1 | 0–2 | `#ff344f` | `#ff2d78` |
| 2 | 3–5 | `#ffc928` | `#f2e51b` |
| 3 | 6–10 | `#38ed6c` | `#22dcff` |
| 4 | 11–15 | `#399bff` | `#b24fff` |

未点亮的暗点用实测色 `#23252a`，不是纯黑 —— 纯黑会让整块屏看起来是空的。

### 16.5 渲染的两个决定

1. **暗点层离屏预渲染，只画一次**。逐帧画 416 个圆是 2.5 万次 `arc/秒`，
   白烧 GPU；参考产品也是离屏贴图 + `drawImage`（`replay` 逆向 §7）。
   每帧只补点亮的点（通常 < 200 个）。
2. **柱状模式不铺暗点层**。柱子上叠一层暗点像「撒了芝麻」，而且柱状本身
   就该是干净的频谱分析仪。两种形态共用同一套分级，所以同频段颜色一致。

四组设置全部落在内核的 `state.appearance`：皮肤不能写 localStorage（§4 不变量 2），
所以只存字符串、由 `AuroraTheme.resolve()` 兜底，两边不各存一份合法值表。

### 17.2 氛围环：不是 CSS 渐变能做出来的

实测结论（`aurora-动态抓取` §7–§9）要求三件 CSS 做不到的事：

1. **彩虹是「按周长参数化」的**，不是锥形渐变 —— 上边 3°→107°、右边 +55°、左边 −55°，
   走一圈正好 360°。锥形渐变绕的是中心点，四边的推进速率不对。
2. **赛博朋克不是单调推进**：左上 338° → 顶中 311° → 右上 272° → 右边下端 229°
   → 底中 191° → 左下 230° → 回左上。是一条**闭合的锚点折线**。
3. **环绕是「亮斑沿周界行进」**，不是整圈明暗同步脉动 —— 实测上/右/左三点相位差
   约 0.5 s、周期 2.0 s。

所以氛围环用 canvas 逐段描边（220 段），颜色 `A.ringColor(frac)`、透明度
`A.ringAlpha(dyn, {t, rms, frac})`。**实测对账**：

| 氛围色 | 顶中 | 右边 | 底中 |
|---|---|---|---|
| 彩虹（实测 3°→107°→…） | H58 | H149 | H237 |
| 赛博朋克（实测 311 / 229 / 191） | **H311** | H244 | **H192** |
| 紫霓 | H266 | H265 | H264（单色，三点一致） |
| 关闭 | alpha 0（整圈消失，与实测一致） | | |

赛博的顶中 311° 与底中 192° 直接对上了截图采样值，说明「锚点 + 周长插值」这个
模型是对的；彩虹与赛博的区别（是否含绿色段）也写成了断言。

### 17.3 四档动态

| 模式 | 公式 | 实测依据 |
|---|---|---|
| 静态 | 恒 1 | 亮度振幅 0.0 |
| 呼吸 | `0.64 + 0.36·(0.5−0.5cos(2πt/3.6))` | 周期 3.6 s，振幅 0.64–1.0 |
| 律动 | `0.64 + 0.36·clamp(rms·2.2)` | 只调亮度不动色相，区间 0.64–1.0 |
| 环绕 | 高斯亮斑，`2.0 s` 一圈，σ=0.075 | 周期 2.0 s，相位沿周界推进 |

**律动没有用「按节拍计数」的做法**：实测它是连续的音频包络（亮度振幅 30–53/255），
用 `rms` 直接映射更贴近，也不用自己猜 BPM 检测。

### 17.4 三档材质

| 材质 | 实现 | 备注 |
|---|---|---|
| 亮面玻璃 | 深色渐变 + 顶部亮边 + 斜向反光 | 默认 |
| 金属面板 | 1px 竖向拉丝纹 + 更强上边缘高光 + 下缘暗边 | 与 Deck 机身的金属感同源 |

模糊层单独放在 `.au-mat`（自己 `overflow:hidden`），**不裁面板** ——
否则设置在面板内的弹出层会被裁掉一半。为此设置弹层改用 `position: fixed`。

### 17.5 打包：改成自动扫描

`build_web.py` / `build_web_pyi.py` 原来各有一份**写死文件名**的 `WEB_STATIC`。
`player/` 是子目录，两份清单都得改，而且漏一处只坏一边（Nuitka 好、PyInstaller 404），
极难查。

改成 **`_player_static()` 自动扫描 `web_ui/player/`**：

- 收 `.js` / `.css`，排除 `*.test.js`（node 单测不进产物）；
- 现在自动覆盖 **11 个文件**（3 个纯逻辑 + 内核 + 两个 Source + ui + 两套皮肤各 js/css）；
- PyInstaller 那边额外处理了**层级**：`--add-data SRC;DEST` 只把文件丢进 DEST 目录、
  不会建 `player/`，所以 DEST 要算成 `web_ui/player`，否则会被摊平到 `web_ui/` 根下。

**以后再加皮肤或纯逻辑模块，打包脚本不用再动。** 这正是当初 `viz.js` 漏打包
导致「两页试听整块失效」那类事故的根因。

### 17.6 顺带修掉的一个 P0′ 回归

`#dlVizEmpty`（「点一首开始试听」）在下载页一直不消失 —— 老代码是在 `playWav()`
里顺手置 `viz.touched = true`，搬进内核后这一步丢了。改成在 `PL.on("state")` 里
「有 id 就收空态」。

这类「顺手写在业务函数里的副作用」是换壳时最容易漏的东西：它不属于任何显式接口，
只能靠**肉眼比对界面**发现，单测和 grep 都抓不到。

## 18. 收尾复核：两处只在「换个量法」时才暴露的问题（2026-11-04 23:5x）

P3 宣布完成后又逐项复核了一遍产物，抓到两个都不会让页面「明显出错」、
但会让改动变脏的东西。

### 18.1 `download.html` 被整体重写成 LF

`git diff --numstat` 报的是 **282 增 / 316 删** —— 一个只有 282 行的文件全改了。
内容其实只动了十几行，其余全是行尾符：仓库里 `download.html` 是 **CRLF**，
而这次编辑它时用了会统一成 LF 的写法。

本仓库的行尾符**没有统一约定**，是按文件历史各自为政的，容易记错：

| 文件 | 约定 |
|---|---|
| `download.html`、`app.js`、`app.css` | CRLF |
| `download.js`、`download.css`、`index.html`、`server.py`、`viz.js`、`build_web*.py` | LF |
| `web_ui/player/*`（本轮新增） | LF（新文件统一 LF） |

还原后 diff 回到 **15 增 / 49 删**，才是真实改动量。

**教训**：判断「这一个文件该用哪种行尾符」，不看仓库里多数文件、也不看编辑器默认值，
只看 `git show HEAD:<path>` 的字节。新增文件才可以自己定（这里定 LF）。

### 18.2 下载页极光皮肤底部被裁 2px

§17.7 说「无溢出」，那次的判据是**逐个元素比对外框**，漏掉了「内容比容器高一点点」
这种情况。换成 `body.scrollHeight - body.clientHeight` 一量：下载页窄版 `ovY = 2`。

拆开算 300px 高的预算：

```
点阵面板 188（矩阵 144 + 工具行 20 + 面板内 gap 8 + padding 16）
pv-main   50（标题 18 + 间距 5 + 进度 6 + 间距 5 + 时间 16）
pv-ctrl   38（播放键直径）
gap       16（两个 8px）
padding   20（10 + 10）
────────────────
         312  >  300     超 12，可见部分是被裁 2px
```

`.pv-ctrl` 底边落在 `662.1`，面板底边 `662` —— 播放键圆底被切掉一条，肉眼几乎看不出，
但确实是破的。

**修法**：窄容器下把 `.au-tools`（「点阵 / 设置」两颗）从「独占一行」改成
`position: absolute; right: 6px; top: 8px` 的竖排，浮进矩阵居中后右侧空出的 40px 里。
面板高度立刻从 188 降到 160（144 + 上下 padding 16），总预算变成 284，留 16px 余量。

为什么不缩点阵：`--dot-pitch` 在窄版是 9px，`level_scale.test.js` 会读 CSS 校验
`calc(26 * var(--dot-pitch))`，改成 8.5 既不是整数（点会糊）又会动到断言。
工具行本来就不属于「点阵」这件事，让它退出排布更干净。

### 18.3 顺带：竖排按钮里的中文会折行

改成浮层后按钮宽 30px、字号 9px，「点阵」两个字正好卡在临界，被压成「点 / 阵」两行，
20px 高装不下就往外顶。加 `white-space: nowrap` 并把 `min-width` 放到 36px 解决。

**竖排容器里的中文短标签一定要显式 `nowrap`**：宽度刚好等于「字数×字号+内边距」时，
浏览器不保证给你留那一两个像素。
