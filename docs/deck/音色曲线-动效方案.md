# 音色曲线显示与动效 —— 技术方案

> 状态：方案，未动产品代码。
> 回答一个问题：AI 母带的「音色」在界面上**怎么画、怎么动**。
>
> 同族：[`点阵与辉光-动效方案.md`](点阵与辉光-动效方案.md)（播放中的实时点阵频谱，与本篇各占一块）
>
> 依赖：[`AI母带-方案.md`](AI母带-方案.md) 的 `presetBands` / `userBands` 数据结构，
> [`音色引擎-分析.md`](音色引擎-分析.md) 的 DSP 链。

---

## 0. 结论

| 决策 | 选择 |
|---|---|
| 载体 | **SVG `<path>`**（不用 Canvas，不用 DOM 柱） |
| 曲线数据 | **真实滤波响应**（`OfflineAudioContext` + `getFrequencyResponse`），不是示意图 |
| 形变动画 | **rAF 手算数组插值**（`path` 的 `d` 不能被 CSS transition，这是硬约束） |
| 出现动画 | **`stroke-dashoffset` CSS transition**，零 rAF |
| 拖动响应 | **无动画**，直接跟随 |
| 让「音色活着」的东西 | **底下那层真实频谱**，不是给曲线加抖动 |

一句话：**曲线本身不该动，它只在两个时刻变 —— 参数改了、有声音进来了。**

## 1. 先排除「画成示意图」这条路

9 段 EQ 的曲线有闭式解，可以直接照公式画一条漂亮的曲线；但那条线是**示意**，不是
「你听到的响应」。差别在两处：

1. `Q` 值、频段间距、`peaking` 的拐点都会让实际响应偏离理想曲线；
2. 将来若有人把 `peaking` 换成 `lowshelf` 或加了 `allpass`，示意曲线不会跟着错，
   而是**继续正确但虚假地**画着。

正确做法是问浏览器要真实响应：

```js
const oc  = new OfflineAudioContext(1, 128, playbackCtx.sampleRate);
const N   = 128;
const f   = new Float32Array(N);
const F0 = 62, F1 = 12000;
for (let i = 0; i < N; i++) f[i] = F0 * Math.pow(F1 / F0, i / (N - 1));

function curveOf(bands) {                 // bands: 9 段增益(dB)
  const total = new Float32Array(N).fill(1);   // 线性幅度相乘
  bands.forEach((g, i) => {
    const bq = oc.createBiquadFilter();
    bq.type = "peaking";
    bq.frequency.value = F0 * Math.pow(F1 / F0, i / 8);
    bq.Q.value = 1.1;
    bq.gain.value = g;
    const mag = new Float32Array(N), ph = new Float32Array(N);
    bq.getFrequencyResponse(f, mag, ph);
    for (let k = 0; k < N; k++) total[k] *= mag[k];
  });
  return Array.from(total, (m) => 20 * Math.log10(m));   // → dB
}
```

三个必须注意的点：

- **采样率要用播放上下文的**（`playbackCtx.sampleRate`），不能写死 44100。
  写死后 12kHz 以上的响应会偏，而芯片音乐最高频段恰好在那里；
- `OfflineAudioContext` 同步可建，**不需要用户手势**，所以「还没播放」时也能画；
- 串联总响应是**各段幅度相乘**，取 dB 后就是相加。别把 dB 直接乘。

## 2. 载体为什么是 SVG

| | **SVG（选它）** | Canvas | DOM 柱 |
|---|---|---|---|
| 主题跟随 | **`stroke="var(--accent)"`，CSS 引擎自动解析，8 套外观零 JS** | 必须像 `viz.js:187` 那样每 500ms 读 `getComputedStyle` | 可以，但只能画柱 |
| 能否画平滑曲线 | 能 | 能 | **不能**，柱状不等于 EQ |
| 缩放 | `aspect-ratio` 下不失真 | 要重算 DPR | 会被拉伸 |
| 叠文字/节点/命中区 | 原生 | 手画 | 原生 |
| 每帧成本 | 只在变时重设 `d` | 每帧整幅重绘 | 每帧改 style |

**第一条是决定性的。** 主题机制已核实：`theme.js:50` 把 6 套复古配色的变量
`style.setProperty` 到 `<html>`，`_palette_vars()`（`server.py:998`）连
`--accent-soft` / `--accent-line` / `--accent-text` 都算好了。

也就是说：**只要写 `stroke="var(--accent)"`，红白机主题（米黄底 + 砖红）和深色主题
下曲线颜色自动正确，一行 JS 都不需要。**

Canvas 做不到这一点 —— `viz.js` 的频谱就是这么被逼着每 500ms 重读一次颜色的
（`themeColors()` 定义在 `viz.js:71`，调用在 `:187`，500ms 节流一次）。曲线不是每帧数据（只有参数变才变），没必要付这个成本。

**顺带一个真实的坑**：复古主题是 `data-theme="retro"`，不匹配 `app.css` 里
`html[data-theme="dark"|"light"]` 那两个块，变量全靠 inline style。所以**绝不能**在
`<style>` 里给曲线写死 fallback 色（比如 `stroke: var(--accent, #8B5CF6)` 后面的
`#8B5CF6`）—— 一旦某个变量没被注入，紫色会突兀地出现在米黄底上。宁可让它无色。

## 3. 三种动画，三种技术

`path` 的 `d` 属性**不能被 CSS transition 插值**（这是 SMIL 才有的事，而 SMIL 已被标记
废弃）。所以必须按场景拆开，各用成本最低的手段：

| 场景 | 技术 | 时长 | 为什么这么选 |
|---|---|---|---|
| **首次出现 / AI 分析中** | `stroke-dasharray` + `dashoffset` 的 CSS transition | 320ms | 从无到有，「画出来」的观感正好对应「正在分析」。纯 CSS，零 rAF |
| **切换预设** | rAF 对**已算好的数组**插值，逐帧重建 `d` | 300ms `ease-out` | `d` 不能 transition，只能手算。缓动先快后慢，像「落定」 |
| **拖动滑块** | **不加动画** | 0 | 拖拽必须跟手。300ms 缓动会让滑块像泡在糖浆里 |
| **播放中** | ~~曲线下方叠一层淡频谱~~ → **已撤销** | — | 由点阵频谱承担，见 [`点阵与辉光-动效方案.md`](点阵与辉光-动效方案.md) §10 |

### 出现动画（零 rAF）

```js
const L = path.getTotalLength();          // ⚠ 必须先挂进 DOM，否则返回 0
path.style.strokeDasharray  = L;
path.style.strokeDashoffset = L;
requestAnimationFrame(() => {             // 强制一次样式计算，否则不会过渡
  path.style.transition = "stroke-dashoffset 320ms cubic-bezier(.4,0,.2,1)";
  path.style.strokeDashoffset = 0;
});
```

用 `cubic-bezier(.4,0,.2,1)`，和项目已有的 `--ease` 一致（`app.css:20`），
不要引入第四种缓动曲线。

### 切换预设（必须 rAF）

```js
let from = curveOf(oldBands), to = curveOf(newBands), t0 = 0;
function step(now) {
  if (!t0) t0 = now;
  const k = Math.min(1, (now - t0) / 300);
  const e = 1 - Math.pow(1 - k, 3);                    // ease-out cubic
  for (let i = 0; i < 128; i++) cur[i] = from[i] + (to[i] - from[i]) * e;
  path.setAttribute("d", toD(cur));
  if (k < 1) RAF.on(step); else RAF.off(step);
}
```

**只插值数组，不重算 `getFrequencyResponse`。** 后者 9 次调用 × 128 点，
放进每帧循环就是浪费 —— 起止两端各算一次就够，中间是纯算术。

### 不要给曲线加「呼吸」

有人会想加一点轻微抖动让它「显得活」。这是假动效：曲线代表静态参数，抖动会让用户以为
参数在变。**它该动的理由只有两个：参数改了、有声音进来了。**

## 4. 组件几何：曲线和滑块是同一个东西

截图里右栏是 9 个竖条滑块。如果曲线另放一块，用户要在两个坐标系之间来回换算。
所以合并成一个组件，**共用同一根 x 轴**：

```
┌──────────────────────────────────────┐
│        ╱‾‾‾╲                         │  ← 曲线区 72px
│  ___╱       ╲___                     │     0dB 基线在正中
├──┬──┬──┬──┬──┬──┬──┬──┬──────────────┤
│▮ │▮ │▮ │▮ │▮ │▮ │▮ │▮ │▮             │  ← 滑块区 28px
└──┴──┴──┴──┴──┴──┴──┴──┴──────────────┘
  62 125 250 500 1k 2k 4k 8k 12k         ← 同一套对数刻度
```

- 滑块 handle 的 x 与曲线节点**严格对齐**（共用同一个频率映射函数，不要各写一份）；
- 拖动时曲线上对应节点放大 1.4× 并给一圈 `--accent-line` 描边；
- 同时出一条竖直参考线（1px 虚线）跟随，松手后 200ms 淡出。

总高 100px 比 9 个独立滑块高不了多少，但信息量完全不同 —— 用户能看见自己拖动的
是**一条曲线上的一个点**，而不是「第 5 格 +3dB」这种抽象数值。

## 5. 双层曲线：让「用户改了多少」可见

这是 `presetBands + userBands` 那套设计在视觉上的对应物：

| 层 | 代表 | 画法 |
|---|---|---|
| 底层 | `presetBands`（AI 给的） | 1px 虚线，`var(--accent)` + `opacity: .4` |
| 上层 | 实际值（相加后 clamp） | 2px 实线，`var(--accent)` |
| 中间填充 | 两者的差 = 用户修饰量 | `var(--accent-soft)`，`fill-opacity: .5` |
| 基线 | 0dB | 1px `var(--border-2)` |

用户一眼看到「这段是 AI 给我的（虚线），我往上推了（实线在虚线上面，中间有填充）」。
关掉 AI 开关时虚线消失、只剩实线 —— **开关的语义自己就表达出来了**，不需要额外文案。

`opacity` 用属性而不是 `rgba()`，因为 `--accent` 在 8 套主题下都是纯色值，
算 alpha 要保持一致；用 `opacity` 就不会和主题里的 `--accent-soft` 打架。

## 6. 让音色看起来「有效果」的东西是频谱，不是曲线

~~播放时在曲线下方叠一层极淡的实时频谱。~~ 

**此条已撤销**：极光皮肤会有一整块点阵频谱（[`点阵与辉光-动效方案.md`](点阵与辉光-动效方案.md)），它把「音乐能量在哪」表达得比一层 10% 的轮廓清楚得多，曲线再叠一层是重复。

数据来源：**直接复用 `viz.js` 的 `V.an` 和 `V.freq`**，不新建 `AnalyserNode`。
原因很硬：`createMediaElementSource` 对同一个元素只能调一次（`viz.js:13` 已记录），
再建一个分析器就得改图，等于把 `音色引擎-分析.md` §5 那一堆坑重走一遍。

效果是：用户看到音乐的能量分布压在音色曲线下面，能直接理解「这条曲线在切什么」。
这比任何「呼吸光效」都有说服力，因为它是真的。

**但必须克制**：中间栏已经有一块大频谱了。所以这层只做轮廓、不填充、透明度压到 10% 以下。
两个频谱抢注意力，比没有频谱更糟。

## 7. 统一 rAF 调度器（顺手修掉一个已知 bug）

项目里目前有 **3 个独立 rAF 循环**：

| 位置 | 用途 |
|---|---|
| `viz.js:286` | 频谱主循环（`V.raf`） |
| `download.js:1113` | 下载页窗口渲染（`sraf`） |
| `download.js:1555` | 双 rAF 等布局重排 |

曲线动画会是第 4 个。加之前应该合并成一个调度器：

```js
const RAF = {
  s: new Set(), id: 0,
  on(fn)  { RAF.s.add(fn);    RAF.start(); },
  off(fn) { RAF.s.delete(fn); if (!RAF.s.size) RAF.stop(); },
  start() {
    if (RAF.id) return;
    const tick = (t) => { RAF.id = requestAnimationFrame(tick); RAF.s.forEach((f) => f(t)); };
    RAF.id = requestAnimationFrame(tick);
  },
  stop() { if (RAF.id) { cancelAnimationFrame(RAF.id); RAF.id = 0; } }
};
```

**它顺手修掉一个已经被记在文档里的坑**：`viz.js:284` 的循环开头是

```js
if (!V.on) { V.raf = 0; return; }
```

也就是说用户一关「显示可视化」，循环就停了 —— 如果 VU 表和曲线也挂在这条循环上，
表针会僵在最后一格，看起来像程序卡死。统一调度后语义可以改对：
**`V.on` 只决定「画不画 canvas」，不再决定「跑不跑循环」**。

另外三个好处：`document.hidden` 时统一暂停、`prefers-reduced-motion` 统一降级、
不用再为「谁先停谁后停」写协调代码。

## 8. 五个具体的坑

| # | 坑 | 表现 | 做法 |
|---|---|---|---|
| 1 | `getFrequencyResponse` 用了错误的采样率 | 12kHz 以上曲线偏离实际听感 | 传 `playbackCtx.sampleRate`；没有 ctx 时退回 44100 并在注释里写明这是近似 |
| 2 | 以为 `d` 能 transition | 切预设时曲线瞬跳，没有过渡 | 只能 rAF 插值（§3） |
| 3 | `getTotalLength()` 返回 0 | 出现动画不播放，曲线直接出现 | **必须先 append 到 DOM 再读长度** |
| 4 | 给变量写了 fallback 颜色 | 复古主题下冒出紫色 | 复古主题靠 inline 变量，`app.css` 里那两个块不生效；**不写 fallback** |
| 5 | 曲线和滑块各写一份频率映射 | 拖动位置与曲线点错位 1–2px | 抽一个 `freqAt(i)`，两处共用 |

第 4 条值得展开：`data-theme="retro"` 时 `html[data-theme="dark"|"light"]` 两个块的变量
**根本不会生效**（`theme.js:11` 的注释就是在说这件事）。所以任何 `var(--x, fallback)`
里的 fallback 都是「暗色主题的色值」，落到米黄底上必然违和。

## 9. `prefers-reduced-motion`：项目目前完全没有支持

`grep prefers-reduced-motion app.css *.js` 在 `web_ui/` 下**零结果**。
也就是说本次新增的动画会是项目里第一个需要处理这件事的动效。

```css
@media (prefers-reduced-motion: reduce) {
  .tone-curve path { transition: none !important; }
}
```

```js
const REDUCED = matchMedia("(prefers-reduced-motion: reduce)").matches;
// 为 true 时：切换预设直接 setAttribute("d", toD(to))，不进插值循环
```

两层都要做：CSS 管 dash 动画，JS 管形变循环。**只做 CSS 管不住 rAF。**

降级后的行为仍然可用：曲线会瞬变，但位置和数值都对。这类用户要的是「别晃」，不是「别更新」。

## 10. 性能预算

| 项 | 成本 | 说明 |
|---|---|---|
| `getFrequencyResponse`（9 段 × 128 点） | ≈ 0.1ms | **只在参数变化时**执行一次 |
| 每帧数组插值 128 点 | ≈ 0.01ms | 纯浮点 |
| 每帧重建 `d` 字符串 | ≈ 0.05ms | 128 个坐标 |
| 曲线区 SVG 重绘 | < 1ms | 单 `<path>` + 2 条填充 |

合计 < 1.5ms/帧，60fps 预算 16.6ms，占 9% 以内。**但前提是不要每帧调
`getFrequencyResponse`** —— 那样会变成 9 × 128 × 每帧，直接吃掉三成预算。

## 11. 验收

| 检查 | 方式 |
|---|---|
| 曲线是真实响应 | 把某段设为 +6dB，断言曲线在对应频率处的值 = `20*log10(响应)`，误差 < 0.2dB |
| 切预设无瞬跳 | 录屏逐帧看，300ms 内连续变化 |
| 拖动跟手 | 鼠标事件到重绘 < 16ms（DevTools Performance） |
| **8 套主题都正确** | 逐套截图，断言曲线颜色 != 兜底紫 `#8B5CF6` |
| reduced-motion | 开启后无过渡，但数值正确 |
| **与 viz 共存** | 关掉「显示可视化」后曲线仍能形变（回归 `viz.js:284` 那个坑） |

最后一条是回归测试里最该有的一条：它验证统一调度器没有把老 bug 带进新代码。

## 12. 待定

1. **曲线区高度**：72px 是估算。若极光面板竖向空间紧张，可压到 56px（视觉上仍可读，
   但 +6dB 与 +3dB 的差别会变难分辨）。
2. **播放中的频谱要不要做**：视觉价值高，但中间栏已经有大频谱，存在抢注意力风险。
   建议先做，看截图再决定保留还是砍。
3. **曲线是否可点击**：点曲线某处直接唤起该段滑块（省一次移动）。与「拖滑块」并存，
   需要先定交互不冲突。
