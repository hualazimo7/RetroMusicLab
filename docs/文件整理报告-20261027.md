# 追加：C 盘暴涨的根因（2026-10-27 21:40）

## 结论

**AI 工具在删除文件前会先复制一份到会话目录**，用来支持撤销。
我今天清掉的 40 GB 里，凡是不在排除名单里的都被复制到了
`C:/Users/xqh/.workbuddy-ai/workspace/sessions/<会话id>/modify_backup/`。

## 对账

`modify_backup/` 里 **31,781 个 `52.d.*` 文件、29 GB**，全部 10-27 生成，
`d` = delete：

| 删掉的 | 体积 | 备份里的证据 |
|---|---|---|
| `D:/MSU1Temp` | 22 GB | 1,439 个测试 wav（含 83 MB 的 `10_STREAM_*.wav`） |
| `msu1-to-cd/_pyi_unpack_tmp` | 6.1 GB | 8,100 pyd + 3,922 dll + 2,295 pyi + 2,520 pxd |
| `build/dist/output/tmp` | 650 MB | 380 个 exe（`MSU1Converter-web.exe` 68 MB、`v4.44.exe` 65 MB） |
| | **≈ 28.8 GB** | **实测 29 GB** ✓ |

反证：`%LOCALAPPDATA%\Temp` 那 11.8 GB **没有被备份** —— 它在会话的
`excluded_backup_roots.json` 排除名单里（`c:/users/xqh/appdata/local/temp`），
`**/__pycache__/**` 同样被排除。机制吻合。

## 为什么全在 C 盘

工具的数据根**固定**是 `%USERPROFILE%\.workbuddy-ai`（即 `C:/Users/xqh/`），
`settings.json` 里没有可以改这个根的项。项目在 D 盘，但 workspace / 备份 /
日志一律写用户目录 —— 于是同一批文件在磁盘上存了两份：
回收站 33 GB + 会话备份 29 GB。

## 已处理

按你的确认清掉会话备份。过程中发现一个现象：删备份时工具会**再备份一次**
（文件名变成 `53.d.*.52.d.*.xxx`），但只复制了 20 个就停了，没有形成循环。

## 以后怎么避免

清大目录（尤其 `D:/MSU1Temp`、`_pyi_unpack_tmp`、`build/`、`dist/`）时，要预料到
工具会复制一份到 C 盘，量级约等于被删体积。两个办法：

1. 清完之后顺手清一次会话的 `modify_backup/`（就是这次做的事）；
2. 或把常用临时目录加进会话的 `excluded_backup_roots.json`
   （`D:/MSU1Temp` 目前**不在**名单里，这是这次暴涨的直接原因）。
